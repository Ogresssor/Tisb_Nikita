
# 2. Разработка программного приложения

## 2.1. Описание структуры и основных методов приложения

### 2.1.1. Выбор средств разработки

Приложение написано на языке **Python** с использованием библиотеки **tkinter** для построения оконного интерфейса и встроенного модуля **sqlite3** для работы с базой данных. Выбор сделан по следующим причинам:

- tkinter и sqlite3 входят в стандартную поставку Python, поэтому для запуска программы не нужно устанавливать дополнительные библиотеки;
- база данных хранится в одном файле рядом с программой, сервер базы данных не требуется;
- программа работает в операционной системе Windows и запускается одной командой.

Состав файлов проекта:

| Файл | Назначение |
|---|---|
| `kinoteatr.py` | программа, 867 строк с комментариями |
| `kino_schema.sql` | создание таблиц, ключей, ограничений, индексов и представлений |
| `kino_dannye.sql` | заполнение таблиц контрольными данными |
| `kinoteatr.db` | файл базы данных |

Если файла базы данных рядом с программой нет, при первом запуске она создаётся автоматически из двух скриптов.

### 2.1.2. Структура приложения

Программа построена по модульному принципу: работа с базой данных отделена от интерфейса. Приложение состоит из пяти классов.

**Класс BazaDannyh** отвечает за подключение к базе данных и выполнение запросов:

Основные методы: `__init__(fayl)` — подключается к файлу базы и включает контроль внешних ключей; `sozdat_bazu()` — создаёт таблицы и заполняет их данными, если файла базы нет; `vybrat(sql, parametry)` — выполняет запрос на выборку и возвращает список записей; `vypolnit(sql, parametry)` — выполняет запрос на изменение данных; `zakryt()` — закрывает соединение.

Все запросы выполняются с параметрами: вместо значений в текст запроса подставляются знаки вопроса, а сами значения передаются отдельно. Это исключает ошибки при вводе кавычек и защищает от подстановки постороннего кода.

**Класс VkladkaSpravochnik** — универсальная вкладка для работы со справочниками. Один класс используется для пяти таблиц (фильмы, залы, клиенты, сотрудники, жанры): при создании ему передаются имя таблицы, список полей и их подписи на русском языке, поэтому один и тот же код не пришлось переписывать пять раз.

Основные методы: `obnovit()` — заполняет таблицу на экране с учётом строки поиска; `vybrat_zapis()` — переносит выбранную строку в поля ввода; `dobavit()`, `izmenit()`, `udalit()` — выполняют запросы INSERT, UPDATE и DELETE; `ochistit()` — очищает поля ввода.

**Класс VkladkaSeansy** — работа с расписанием. Фильм и зал выбираются из выпадающих списков, поэтому ввести несуществующий код нельзя. Методы добавления, изменения и удаления обрабатывают ошибки целостности: при попытке назначить два сеанса в одном зале на одно время выводится понятное сообщение, при попытке удалить сеанс с проданными билетами — предупреждение.

**Класс VkladkaBilety** — продажа и возврат билетов:

Основные методы: `zagruzit_spiski()` — загружает списки сеансов, клиентов и кассиров; `vybran_seans()` — ограничивает номера ряда и места размерами выбранного зала; `poschitat_cenu()` — рассчитывает цену билета с учётом скидки; `prodat()` — продаёт билет с проверкой занятости места; `pokazat_svobodnye()` — показывает свободные и занятые места; `vernut()` — оформляет возврат билета.

**Класс VkladkaOtchety** — построение отчётов. Метод `podstavit_parametry()` автоматически подставляет в поля подходящие значения (например, границы периода продаж), метод `postroit()` выполняет запрос выбранного отчёта и выводит результат на экран.

**Класс GlavnoeOkno** — главное окно программы: создаёт подключение к базе данных, восемь вкладок и корректно закрывает соединение при выходе.

### 2.1.3. Реализованные функции

1. **Ведение справочников** — добавление, изменение и удаление фильмов, залов, клиентов, сотрудников и жанров.
2. **Поиск и отбор информации** — поиск по справочникам сразу по нескольким полям, отбор расписания по дате, отбор фильмов по жанру.
3. **Составление расписания** — добавление сеансов с контролем занятости залов.
4. **Продажа билетов** — автоматический расчёт цены с учётом скидки клиента, контроль занятости мест, просмотр свободных мест.
5. **Возврат билетов** — изменение статуса билета.
6. **Отчёты** — шесть отчётов о работе кинотеатра.

### 2.1.4. Пример реализации: продажа билета

Продажа билета — наиболее показательная операция, в которой участвуют несколько таблиц и проверок. Метод `prodat()` проверяет, что выбраны сеанс и кассир, что номера ряда и места не выходят за размеры зала, определяет размер скидки клиента (для покупателя без карты она равна нулю) и выполняет вставку записи в таблицу BILET. Если место уже продано, база данных отклоняет вставку по ограничению UNIQUE, и программа показывает понятное сообщение; при успешной продаже выводится итоговая стоимость, рассчитанная вычисляемым столбцом.

```python
try:
    self.bd.vypolnit(
        'INSERT INTO bilet (id_seansa, id_klienta, id_sotrudnika, ryad, mesto, '
        'data_prodazhi, cena_bez_skidki, skidka_procent, status) '
        "VALUES (?, ?, ?, ?, ?, date('now'), ?, ?, 'продан')",
        (seans['id_seansa'], kod_klienta, kod_sotrudnika, ryad, mesto,
         seans['bazovaya_cena'], skidka))
except sqlite3.IntegrityError:
    messagebox.showerror('Ошибка',
                         f'Место {mesto} в ряду {ryad} на этот сеанс уже продано.')
    return
```

Таким образом, правила, заданные при проектировании базы данных, продолжают работать и из приложения: программа не обходит ограничения, а сообщает пользователю о них понятным языком.

### 2.2.3. Инструкция по использованию системы

1. **Запуск.** Поместить файлы `kinoteatr.py`, `kino_schema.sql`, `kino_dannye.sql` и `kinoteatr.db` в одну папку и выполнить команду `python kinoteatr.py`. Требуется Python версии 3.8 или новее; дополнительные библиотеки устанавливать не нужно.
2. **Расписание.** Вкладка «Сеансы»: ввести дату и нажать «Показать расписание»; кнопка «Все сеансы» снимает отбор. Чтобы добавить сеанс, выбрать фильм и зал, ввести дату, время, цену и формат, нажать «Добавить сеанс». Чтобы изменить сеанс, выбрать его в таблице, исправить поля и нажать «Изменить».
3. **Продажа билета.** Вкладка «Продажа билетов»: выбрать сеанс, клиента (или «без карты»), кассира, указать ряд и место, нажать «Продать билет». Кнопка «Свободные места» показывает, какие места заняты и сколько свободно.
4. **Возврат билета.** Выбрать билет в таблице и нажать «Вернуть билет»: статус билета изменится на «возвращён», место снова станет свободным.
5. **Справочники.** Вкладки «Фильмы», «Залы», «Клиенты», «Сотрудники», «Жанры»: выбрать запись в таблице — её значения появятся в полях ввода; кнопки «Добавить», «Изменить», «Удалить» выполняют соответствующие действия. Строка поиска отбирает записи сразу по нескольким полям.
6. **Отчёты.** Вкладка «Отчёты»: выбрать отчёт из списка — параметры подставятся автоматически; при необходимости изменить их и нажать «Построить отчёт».

# Заключение

В ходе курсового проекта спроектирована и разработана база данных «Кинотеатр» и программное приложение для работы с ней.

Проведено исследование предметной области: описана работа кинотеатра, определены пользователи системы, сформулированы семь функций системы и восемь запросов к базе данных с указанием входных и выходных данных.

Построена инфологическая модель: выделено семь наборов объектов с атрибутами и ключами, установлено шесть связей. Связь «многие ко многим» между фильмами и жанрами разделена на две связи «один ко многим» через дополнительную сущность.

Инфологическая модель преобразована в схему реляционной базы данных из восьми таблиц, связи заданы семью внешними ключами. Предусмотрены два вычисляемых столбца и два представления для отчётности. Схема приведена к третьей нормальной форме и дополнена правилами целостности. Структура реализована средствами СУБД SQLite, таблицы заполнены контрольными данными — не менее десяти записей в каждой.

Разработано приложение на языке Python с оконным интерфейсом из пяти классов и восьми вкладок: ведение справочников, расписание, продажа и возврат билетов с автоматическим расчётом цены, поиск и отбор информации, шесть отчётов. Приложение отлажено и протестировано по девяти проверкам, включая попытки внести некорректные данные; все такие операции отклоняются с понятным сообщением, ошибок в работе не выявлено.

Цель курсового проекта достигнута, все поставленные задачи выполнены. Разработанная система может использоваться кассирами, администраторами и руководителем кинотеатра для ведения расписания, продажи билетов и получения отчётности. Направления дальнейшего развития: введение ценовых категорий мест, продажа билетов через сайт, система абонементов и бонусных баллов, а также учёт нескольких кинотеатров сети — структура базы данных позволяет внести эти изменения добавлением новых таблиц и полей без перестройки существующих связей.
