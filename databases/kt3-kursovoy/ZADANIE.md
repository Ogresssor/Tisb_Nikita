# КТ3 — курсовой проект по дисциплине «Базы данных»

- Тип КТ: курсовой проект
- Количество вопросов: 1
- Отведено времени: 2 месяца

## Тема

**Проектирование и разработка базы данных «Кинотеатр»**

Тема выбрана из списка кафедры. На момент записи задания тема **не утверждена
преподавателем** — начинать выполнение можно только после утверждения.

## Требования (из файла «Требования к курсовой.pdf»)

Цель — приобретение практических навыков формулирования требований к базам данных,
построения их моделей и разработки программных приложений.

Что нужно сделать:

- исследовать предметную область и сформулировать перечень задач;
- построить инфологическую модель объекта учёта;
- построить логическую модель;
- спроектировать и построить физическую структуру данных в выбранной СУБД;
- разработать и отладить программное приложение для работы с БД;
- заполнить таблицы контрольными данными и провести тестирование;
- реализовать функции добавления, удаления, поиска и отбора информации;
- оформить пояснительную записку.

Требования к приложению:

- количество таблиц — не менее 4;
- наличие связанных таблиц;
- наличие вычисляемых столбцов;
- размер таблиц — не менее 10 записей.

### Структура пояснительной записки

- Титульный лист
- Содержание
- Введение (актуальность, цель, задачи, краткое содержание работы)
- 1. Постановка задачи
  - 1.1. Теоретические сведения по проектированию реляционных баз данных
  - 1.2. Анализ предметной области: обследование организации, предпроектный анализ
    потребностей пользователей, выявление основных сущностей и их связей
  - 1.3. Модель «сущность — связь» для базы данных задачи
  - 1.4. Схема реляционной базы данных задачи
- 2. Разработка программного приложения
  - 2.1. Описание структуры и основных методов (процедур и функций) приложения
  - 2.2. Результаты тестирования с примерами визуальных форм и инструкции по использованию
- Список литературы (источники за последние 3–4 года)
- Приложение 1. Исходные тексты приложения с краткими комментариями

Объём: 30–35 страниц (25 страниц текста и 10–15 страниц листинга программ).

Отдельно в требованиях описана последовательность построения ER-диаграммы: выписать
функции и запросы БД, выделить существительные (будущие сущности), определить атрибуты
и ключевые атрибуты, расставить связи, а связи «многие ко многим» разделить на две
связи «один ко многим» через дополнительную сущность.

### Принятые решения

- Приложение делаем **настольным, под Windows**, база данных — **файл БД** рядом
  с программой (без установки сервера), чтобы преподаватель мог просто открыть и запустить.
- Черновая структура БД: залы, фильмы, жанры (связь «многие ко многим» через
  дополнительную таблицу), сеансы, клиенты, сотрудники-кассиры, билеты.
  Вычисляемые столбцы: итоговая цена билета со скидкой, количество мест в зале,
  выручка и заполненность по сеансу.

### Статус

Работа отложена — вернуться к ней после других предметов. Тема на момент записи
не утверждена преподавателем.

## План работы (черновой, уточнится после требований)

1. Введение: назначение БД, задачи кинотеатра, которые она решает.
2. Анализ предметной области: залы, места, фильмы, сеансы, билеты, цены, сотрудники, клиенты.
3. Инфологическая модель: сущности, атрибуты, связи, ER-диаграмма.
4. Переход к реляционной схеме: таблицы, первичные и внешние ключи, нормализация до 3НФ.
5. Реализация в СУБД: скрипты создания таблиц, заполнение данными.
6. Запросы: расписание сеансов, свободные места, выручка по фильмам и т. д.
7. Заключение, список литературы, приложения.
